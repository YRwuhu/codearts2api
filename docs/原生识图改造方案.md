# CodeArts2API 原生识图改造方案（v0.6.0）

> 目标：把现在「附件上传 + CloudAgent 会话 + analyzeImage 工具」的曲线识图，
> 改成直接走 `POST /api/v2/chat/completions` 的模型原生识图。
>
> 本文是改造前的方案文档，实际实现以仓库代码为准。探测时间：2026-11-04。

---

## 1. 背景

插件当前对「含图片的请求」有一套曲线方案：

1. 用户请求的模型在 `/v1/model/builtin` 里 `supports_images=false`；
2. 于是插件新建 CloudAgent 会话、multipart 上传附件；
3. 用 `agent: build` + `context_part` 提交网页任务；
4. 等 CloudAgent 的 `analyzeImage` 工具返回图片描述；
5. 失败还要读会话里的 `ImageId` 再重试；
6. 再失败才切 `CODEARTS_VISION_MODEL`。

这条链路 20–40 秒、受「每账号 3 个会话」限制、代码量约 1200 行。
上游现在已经支持模型原生识图，上述曲线可以整体删除。

## 2. 实测结论（决定性证据）

用真实 AK/SK 直接签名请求上游 `POST /api/v2/chat/completions`，
消息体使用标准 OpenAI 图片块：

```json
{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}
```

| 模型 | 原生识图 | 实测结果 |
|---|---|---|
| deepseek-v4.1-flash-1017 | 支持 | HTTP 200，prompt_tokens 229，思维链复述图片内容 |
| deepseek-v4.1-flash | 支持 | HTTP 200，同上 |
| speed | 支持 | HTTP 200，与 deepseek 同特征 |
| kimi-k3 | 支持 | HTTP 200，直接回答「红色」 |
| kimi-k3.1-pro | 支持 | HTTP 200，思维链描述图片 |
| glm-5.3-flash | 支持 | HTTP 200 |
| Qwen3-VL-235B | 支持 | HTTP 200 |
| kimi-k2.6-vl | 支持 | HTTP 200 |
| glm-5.3 | 拒绝 | HTTP 406 `InferHub.001001020.406` `The request model is not multimodal` |
| GLM-5.2 | 拒绝 | HTTP 406，同上 |
| glm-5.2-sft-harmony | 拒绝 | HTTP 406，同上 |
| openpangu-2.0-pro | 拒绝 | HTTP 406，同上 |
| openpangu-2.0-flash | 拒绝 | HTTP 406，同上 |
| deepseek-v4-pro-0813 | 无权限 | `TM.000010051`，账号未开通，未测出能力 |

其它关键结论：

1. **上游元数据不可信**：`GET /v1/model/builtin`（`Agent-Type: PromptCenter`）
   和 AgentCenter 的 `model_parameters.supports_images` 对 `deepseek-v4.1-flash-1017`
   仍然返回 `false`，但直连接口实际能读图。该字段只描述 IDE 的图片注入链路。
2. **只接受 data URL**：传 `https://...png` 会被
   `400 ModelArts.81001 Invalid request: unsupported image url` 拒绝。
3. PNG / JPEG / WebP / GIF 都接受；一次多图接受；`detail` 字段被容忍。
4. `stream: true` 时原生图片流正常，首帧约 1.2–2 秒。
5. 406 是**模型级**拒绝，换账号没有意义，不能按账号故障切换处理。

## 3. 目标形态

```
客户端带图
  → 参数归一化（data URL / MIME / 单图大小校验）
  → POST /api/v2/chat/completions（用户所选的模型）
      ├─ 200：原生识图，真流式返回（首帧 1–2 秒）
      └─ 406 not multimodal：
           ├─ 标记该模型为「纯文本」
           ├─ 有回退模型 → 改用回退模型重发一次
           └─ 回退关闭/不可用 → 返回可读的 400
```

核心原则：**不再用上游 `supports_images` 决定走哪条链路**。
先按用户所选模型原生发送，失败后再回退；这样上游以后新增多模态模型，
不改代码也能自动吃到。

## 4. 已确认决策

| # | 决策点 | 结论 |
|---|---|---|
| 1 | CloudAgent 通道 | **彻底删除**（代码、模块、启动回收器、依赖 feature） |
| 2 | 纯文本模型收到图片 | **方案 A**：自动改用 `CODEARTS_VISION_MODEL` 重发一次；`off` 则报错 |
| 3 | 默认回退模型 | `deepseek-v4.1-flash-1017`（原生多模态，实测可用） |
| 4 | 远程图片 URL | 本地**方案 A**：直接返回可读 400；**方案 B** 作为可选路径写在 5.4 节 |

## 5. 新链路设计

### 5.1 能力判定（三源合并）

1. **实测 allowlist**（`models.rs` 的 `NATIVE_VISION_MODELS`）：
   deepseek-v4.1-flash / deepseek-v4.1-flash-1017 / kimi-k3 / kimi-k3.1-pro /
   glm-5.3-flash / speed / Qwen3-VL-235B / kimi-k2.6-vl。
2. **上游目录标记**：`/v1/model/builtin` 或 AgentCenter 报 `true` 的也算。
3. **运行时观察**（进程内）：某模型原生读图成功一次 → 记 `true`；
   收到 406 → 记 `false`。之后相同模型走快速路径，不再多付一次 406 往返。

`/v1/models` 的 `supports_images`、`vision`、`supports_vision`、
`input_modalities` 都按上述合并结果输出，不再被上游的 `false` 覆盖。

新增模型可以不用改代码：未登记模型第一次带图会先试原生，成功就自动学习为可用；
也支持用 `CODEARTS_EXTRA_VISION_MODELS` 环境变量（逗号分隔）显式追加。

### 5.2 406 处理

- 收到 406 且消息含 `model is not multimodal`（或错误码
  `InferHub.001001020.406`）→ 归类为 `model_not_multimodal`：
  - HTTP 400，**不换账号、不计入账号失败**（避免把账号打冷却）；
  - 记录 `vision=false`；
  - 若开启了回退，仅在**本次请求还没输出任何字节**时用回退模型重发一次；
  - 回退模型本身也 406 时不再重试，直接返回错误。
- `CODEARTS_VISION_MODEL` 语义：
  - 默认 `deepseek-v4.1-flash-1017`；
  - 设为 `off` 表示关闭自动回退，纯文本模型收到图片直接返回 400；
  - 与当前模型相同、或为空时同样不启用回退，三种原因是分开报的。

**流式请求的回退边界**：`stream: true` 时上游在流内部回 406，属于「已经开始
输出」的失败 —— 响应头早已发给客户端，此时换模型重发会让客户端看到两份内容。
因此流内 406 直接作为终止错误返回，只保证**不计入账号失败**、不触发账号冷却，
不做流内回退。`stream: false` 才有完整的一次回退。

### 5.3 图片入参校验（本地前置）

在发上游前做，避免白烧额度：

- 只接受 `data:image/...;base64,...`；
- MIME 白名单：PNG、JPEG、WebP、GIF；
- 单图解码后不超过 20 MiB、内容非空；
- 缺少 URL、非 base64、data URL 格式错误 → 清晰的 400；
- 校验与「请求里有没有图」合并成一次遍历，不再重复扫描整个 body；
- base64 体积估算在超过上限时提前返回，不会为一张超限图片扫完整个字符串。

### 5.4 远程图片 URL

当前实现直接拒绝 `http(s)://` 图片 URL，返回 `400`，提示客户端内联为 base64
data URL。原因是上游 `/api/v2/chat/completions` 只认 data URL，传链接会被
`ModelArts.81001 unsupported image url` 拒绝；在本地拦住可以省掉一次注定失败
的往返，也没有额外网络副作用。**代理不做下载转码**（避免引入 SSRF 面与额外
超时/大小预算），需要的用户请先在客户端把图片内联。

## 7. 测试与验收

### 单元测试

- `native_vision` allowlist 大小写不敏感、未知模型不误判；
- `supports_images` 不被上游 `false` 覆盖；
- 406 分类为 `model_not_multimodal`、`switch_account=false`；
- `is_account_failure`：`model_not_multimodal` 为 false，其余故障码为 true
  （流内与流间共用同一判定）；
- `VisionFallback` 四种原因（off / 空 / 与当前模型相同 / 可用）各一条，
  且三种「不启用」的文案互不相同；
- 图片校验：PNG/JPEG/WebP/GIF 通过；远程 URL、非 base64、空图、未知 MIME 报错；
  校验同时返回「是否带图」，三种协议形状都识别得到；
- base64 体积估算超过上限即停，不再扫完整字符串；
- `CODEARTS_EXTRA_VISION_MODELS` 解析忽略空白/空项、大小写不敏感；
- 旧的 CloudAgent 测试全部移除，其余协议测试保持通过。

### 端到端验收

1. `cargo test` 全绿；
2. `cargo build --release` 产出新 exe；
3. 起新实例后：
   - `GET /v1/models` 中 deepseek-v4.1-flash-1017 等 `supports_images=true`；
   - 带图请求 deepseek 走原生，首帧 1–2 秒，无 CloudAgent 会话产生；
   - 带图请求 `glm-5.3`：第一次 406 后回退 `deepseek-v4.1-flash-1017` 成功；
   - 带图请求远程 URL 立即 400；
   - `stream: true` 正常；
   - CloudAgent 会话列表不再增长。

## 8. 风险与回滚

- **风险**：上游若调整原生图片格式（例如要求别的 content 形状），会集中 400/406；
  日志里会打印上游 `error_code` 与 `error_msg`，便于定位。
- **风险**：回退模型不可用（未开通）时，纯文本模型的图片请求会失败；
  错误信息会明确提示改配置或换模型。
- **回滚**：CloudAgent 实现保留在 git 历史（删除前提交点 `d0978ae`），
  需要时可整体 revert；版本号回退到 0.5.x。
- **兼容性**：`/v1/models` 删除了自定义字段 `supports_attachments`；
  这是本项目的私有字段，不属于 OpenAI 规范。

## 9. 附录：探测方法

使用账号的 AK/SK 按华为云 `SDK-HMAC-SHA256` 签名直连：

```
POST https://snap-access.cn-north-4.myhuaweicloud.com/api/v2/chat/completions
X-Ot-Session-Id / User-Session-Id: ses_<sha256(AK)[..24]>
Model-Id / Model-Name: <model>
Authorization: SDK-HMAC-SHA256 Access=..., SignedHeaders=..., Signature=...
```

请求体为普通 OpenAI chat 结构，图片用 48×48 PNG 的 data URL；
每次探测约 200–250 prompt tokens。406 响应体示例：

```json
{"error_code":"InferHub.001001020.406","error_msg":"The request model is not multimodal","details":[]}
```

远程 URL 拒绝示例：

```json
{"error":{"code":"ModelArts.81001","message":"Invalid request: unsupported image url: https://..."}}
```

## 11. 复审修正（发布前）

PR 复审发现的问题在 0.6.0 发布前全部修掉：

1. **流内 406 会计入账号失败**：`sse_stream` 里无条件 `gate.note_failure`，
   连续 3 次带图 406 会把健康账号打成冷却。改为与 `run_for_model` 共用
   `is_account_failure()`，模型能力错误一律不记账。
2. **提前回退跳过 `wait_for_model`**：已确认纯文本的模型直接换回退模型时，
   若该模型还没进目录，会报 `404 model '<vision>' 不在当前账号可用模型列表中`
   —— 一个调用方从没指定过的模型名。现在补了同样的等待窗口，不可用时返回
   带原因的 400。
3. **`vision_fallback` 的 `None` 混了三种原因**：错误文案一律说成
   `CODEARTS_VISION_MODEL=off`，但实际也可能是空值或与当前模型相同。
   改为 `VisionFallback` 枚举，按原因给文案。
4. **能力学习时机偏乐观**：原来拿到响应头就记 `vision=true`，流随即失败也算
   能识图。改为只在上游完整返回（`Outcome::Json`）时记账，流式不记。
5. **删除 CloudAgent 遗留死代码**：`Catalog::signed_request`、
   `Catalog::http_client`、`Catalog::supports_images`、`Pool::supports_images`
   已无调用方，连同只测它们的用例一起删除。
6. **性能**：图片校验与「是否有图」合并为一次遍历；`base64` 体积估算超限即停；
   视觉 allowlist 与 `CODEARTS_EXTRA_VISION_MODELS` 用 `OnceLock` 缓存，
   不再按模型重复读环境变量；请求内 `Config` 只取一次快照（原先每个账号
   循环、每次用量记账都会克隆整份配置）；`record_usage` 复用已持有的
   `AccountGate`，不再查表重建。
7. **降级路径的 usage 帧**：`stream: true` 但上游回了普通 JSON 时，旧的
   单帧包装会丢掉 `usage`；改用与另一条降级路径相同的两帧形态。
